# 为什么链长增加后修正幅度收缩

**2026-10-13 更新：服务器已确认 CUDA BF16 图均值错误，应优先修复。下文原运动量是旧导出的观测值，原梯度分析暂不作为正常数值路径下的因果证据。** 见[修复与复评说明](../../scripts/FP32_GRAPH_MEAN_FIX.md)。

目前能确认现象和部分机制，尚不能把所有长链静止归结为一个已证明的原因。证据来自源码、本地三结构、五目标探针及 2026-09-30 数据生命周期快照。

## 1. 现象是原始向量输出变小，不是多数 gate 关闭

测试链移动 RMS 的组平均：≤50 nt 为 2.467 Å，51–100 nt 为 1.159 Å，101–200 nt 为 1.468 Å，>200 nt 为 0.151 Å。不是每个目标都随长度严格单调，而是超长组明显收缩。

7ZJ4（374 nt）gate 均值 0.908，raw RMS 0.329 → 门控后 0.318 Å；9C6J（495 nt）gate 均值 0.748，raw RMS 只有 0.00194 Å。因此应首先研究为什么网络生成不了有效的长链修正，而不是只调 gate。

## 2. 实际长链训练结构很少

按 `Code/pipeline_reports/DATA_V2_FOLDBENCH_TEST_OVERRIDE_20260930T081218Z/pdb_lifecycle.tsv` 的 `FINAL_SPLIT=train` 且 `PT_COUNT>0` 统计：

| 长度 | PDB 数 | PT 数 |
| --- | ---: | ---: |
| ≤50 nt | 476 | 95,200 |
| 51–100 nt | 180 | 36,000 |
| 101–200 nt | 77 | 15,370 |
| >200 nt | 25 | 4,650 |

有 PT 的训练结构共 758 个，>200 nt 只占 **3.30%**。当前测试 19/67 为 >200 nt，即 **28.36%**；验证集为 22/103，即 21.36%。这说明长链泛化面对明显不同的长度分布。

训练上采样仅把所有 >50 nt 的 PT 赋权 2：>200 nt 的加权份额为 `2×4650 / (95200 + 2×(36000+15370+4650)) = 4.49%`。一个 60 nt RNA 与一个 500 nt RNA得到相同权重，无法专门补齐超长链。

这是历史快照，不是对服务器当前 train 的实时审计。50×4 候选增加同一 RNA 的输入构象，但不会把 25 个长 RNA 变成 5000 种独立结构拓扑。

## 3. 网络主要从局部三维邻域生成一步修正

当前配置：6 层原子图消息传递，动态空间边半径 6 Å（另有静态共价/序列边），一次 residual 输出。

长 RNA 可能每个螺旋内部几何都合理，只是螺旋/结构域之间的相对位置、角度或连接关系错误。局部邻域可以描述化学环境，却未必能决定一个远处结构域该往哪个方向移动。当前没有显式结构域级几何协调模块；PAE/PDE/contact 特征主要在已有邻接边上使用，不等于建立全部远距离几何交互。

RNA-FM 的全链序列语义也不等于远距离结构域的三维位置关系。源条件分支仍存在，但 residual 中当前位置就是源位置、t=0；并不是经过多步更新不断重算坐标和修正方向。

数据上，测试 ≤50 nt 的修正/目标位移方向余弦均值约 0.330，>200 nt 约 **0.021**；验证 >200 nt 为 0.0034。长链不仅幅度小，已有动作也几乎没有整体对准目标方向。这支持“方向能力不足”的候选解释，但不能只凭相关性证明架构因果。

## 4. no-regret 可进一步抑制部分长链修正

此节为错误均值路径上的旧探针结果，需修复后重新验证。

7ZJ4 的加权 no-regret 参数梯度达到坐标项的 77.2%，余弦 −0.695，抵消坐标方向约 53.7% 的梯度分量。逐残基不允许变差的要求，可能与多个结构域共同重排的坐标下降方向竞争。

但 9C6J 的 no-regret 与坐标项余弦 +0.860，因此不能把所有长链都解释成 no-regret 冲突。budget、protect、几何项也没有在这两个目标上表现为共同主导的阻力。

## 5. 长度归一化和有限数据可能放大偏差

坐标项为 `L=(1/N_observed)∑||v_i-u_i||₂`。每个原子的直接梯度大约按 `1/N_observed` 缩放，误差很大时也不会像 MSE 那样按误差幅度增加；修好一个局部区域，在长链总损失中的份额较小。

这是防止长链支配训练的常见归一化目的，本身不意味着输出必然随 N 变小：参数梯度还会跨原子累加，局部/全局方向也会影响抵消。与超长结构稀少、一步局部预测结合后，它是值得检查的放大因素。

## 6. 服务器已确认低精度图均值错误

9C6J 的门控后 RMS / raw RMS =1.812，违反理想 gate+去质心的收缩性质。另外，8324 个可观测原子的平均欧氏坐标损失，其对 raw 输出的梯度在正确 gate/去质心下应受约 `1/√8324=0.01096` 的上界约束；实测为 0.04885。7ZJ4 的对应上界约 0.01119，实测为 0.04526。两个长链都超过理想上界约四倍，短链则没有这一明显违反。

服务器实际 Torch 2.7.1+cu126 / PyG / CUDA 检查已确认：BF16 下 576、2048、4096、7984、10629、20000 个原子的计数均停在 256，FP32 正常。7984 / 10629 个原子的坐标梯度上界比达到 14.93 / 19.99。向量输出为 BF16，网络原始速度及 gate 后速度的去质心都经过该问题路径。错误影响前向和反向，强度随原子数增加，但对长链收缩的最终贡献仍需复评与受控训练实验。

已修复项目均值：求和提升为 FP32、计数为整数、去质心结果保持 FP32，覆盖反向广播归约。更新检查脚本区分原始 `backend_*` 故障对照和修复后的 `production_*`。

上传并解压修复包后执行（检查本身不需要真实 PT/权重）：

```bash
conda activate protenix-1.0.5
cd ~/Code_Flow_matching
CUDA_VISIBLE_DEVICES=3 python scripts/check_bf16_graph_mean.py --device cuda --assert-fixed
```

通过条件：`production_dtype=torch.float32`、`production_constant_center_error≈0`、`gate_RMS_ratio≤1`、`coordinate_gradient_bound_ratio≤1`。原始 backend 的 count 仍可能为 256；`mean_ones≈1` 无法排除分子和分母同时出错。

## 当前最合理的解释与顺序

目前已明确存在低精度归约错误，它直接影响长链训练和推理的数值路径。长链样本不足、局部一步预测能力及 no-regret 冲突仍是候选解释，特别是原梯度应重新测量。gate 整体关闭不符合旧探针的两个长链观测。

先修图均值并用同一旧权重复评 BF16/FP32，分离推理误差。旧权重的训练历史不会被推理修复消除，检验训练影响需要受控重新训练。修复后再用验证集检查超长链采样、损失权重及全局几何表达。现阶段不要依据旧梯度直接放松 no-regret 或统一放大输出。
